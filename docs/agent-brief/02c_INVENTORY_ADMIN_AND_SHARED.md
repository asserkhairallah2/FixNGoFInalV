## A. Admin (`06_Admin.js`)

Tabs: Overview (AD01), Verify (AD02), Users (AD04), Pricing (AD05), Profile (AD06). Main screens: AD01, AD02, AD04, AD05, AD06.
Fallback-back: AD03→AD02, AD07→AD01, AD08→AD07, AD09→AD01, AD10→AD09, AD11→AD04, AD12→AD11, AD13→AD06, AD14→AD13, AD15→AD03.
The admin account **never self-registers**: the first admin is created by `setup.bat`. Additional admins can be created only by an existing admin (add a small "Invite admin" action in AD06 — SHOULD). Admins with 2FA enabled must pass TOTP at login.

### Added admin screens (SHOULD — required by SRS UC-30/UC-31)
- **AD16 Reports** (`GET /admin/reports?period&from&to`): requests by status/type, active providers, payments (cash vs online), average ratings, new users per day (simple table + bar charts in the existing visual style), CSV export.
- **AD17 Reviews & complaints**: list of reported/flagged reviews and complaints; keep / hide review (recomputes provider rating) / resolve complaint; link to AD12 for misconduct.
- **AD18 Support inbox**: list tickets (SH08 creates them), open one, reply (shows in SH09 for the user), change status (Open/Awaiting support/Answered/Closed).

Audit log: every admin write action (verification decision, access decision, payment review, safety decision, settings change, review moderation, support reply, admin invite) writes `AuditLog {actorId, action, entityType, entityId, reason/note, before/after JSON, at}`. Provide `GET /admin/audit-logs` (and show it in AD16 or a small "Audit" section).

## B. Shared (`07_SharedSettings.js`)

Tab highlight by screen: Home (SH03, SH19), Requests (SH01, SH04), Earnings (SH14–SH16, SH20), Profile (the rest). Internal fallback-back: SH08→SH07, SH09→SH07 (**fix: was SH08**), SH16→SH15, SH18→SH17, SH20→SH14. Other shared screens return to the role's profile/home by `lastRole`. **All shared screens must read the logged-in user from the session** (the prototype hard-codes Ahmed/Karim/Mahmoud per screen). **Unknown screen id must show a NotFound screen, never SH21.**
