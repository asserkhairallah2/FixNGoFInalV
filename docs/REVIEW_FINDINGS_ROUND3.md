Effects: a brand-new owner sees a phantom **"ACTIVE REQUEST • FG-1042 · En route"** on Home (C02); flatbed-tow C13 shows battery/alternator items; centers show fake `4.8 (35 reviews)` / `4.8 (48)`; candidate cards show seeded rating "4.8 (42)"/"4.9". **Remove every `|| 'literal'` data fallback in all modules** (search for `|| '`, `?? '`, `||` followed by a digit/EGP/name, and any `t('…')` containing sample data). Show an honest empty/loading state instead. **Extend `tools/mock-scan.ps1`** to flag: `\|\|\s*'[A-Z]{1,3}-\d{3,4}'`, `\|\|\s*\d`, "alternator", "Verified FixNGo Specialist", "Your FixNGo Specialist", fake rating patterns, and fail the build on any hit (the current scan reported 0 hits while these existed).
2. **Offer notification deep link broken:** clicking a "New offer" notification (Dock/C22) navigates to `#/offer:<id>` → "Screen not available", and returning home resets captain duty to OFF. Notification deep links must map to real screen codes + params (offer → T03/M03 with id; request → C11; booking → C38/SC03; etc.). Add a test for every notification type's deep link.
3. **Re-dispatch of an expired offer returns HTTP 500** (`POST /requests/{id}/offers`) and the captain dashboard still shows "Continue Active Trip" for that request while its detail endpoint returns 403. Expired/withdrawn offers must never leave a stale active-trip card; re-dispatch must return a clean 409/200 with proper state.
4. **Captain/mechanic earnings & rating do not update after completion:** T09 shows 0.00 balance / 0 jobs / "No wallet transactions" and rating 0.0 after a completed, cash-confirmed, 5-star-rated trip (T01 shows the trip count and 695.55 earnings, so data exists). Wallet entry must be created on completion; rating aggregate recomputed; T09/T10/M07/M09 must read them.
5. **Invoice/payment state wrong (C15):** after "Confirm cash handed to provider" (200 OK) the badge stays `Unpaid`; line items (695.55 + 65 fee) don't sum to the total; "Total settled" shown while unpaid. Fix status transitions (cash confirmed by provider + customer ⇒ `Paid`) and totals. Service-center invoice extra lines (e.g. Oil Filter 75) must appear on the owner's C37/C38 booking/invoice.
6. **Admin document viewer SH17 is wrong:** shows the logged-in admin's own KYC (`Review Admin`, `KYC-0000`, "Not submitted") and a generic placeholder instead of the applicant's uploaded file; offers "Replace document" to the admin; highlights Profile tab. SH17 must take a document id, stream the real uploaded image/PDF via the authorised endpoint, show the applicant's holder/type/date/status, and hide Replace for admins.
